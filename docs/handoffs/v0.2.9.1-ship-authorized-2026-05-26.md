## Non-blocking follow-up: register classifier grader fix

The auto-grader has KNOWN false-negative patterns confirmed by this iteration AND by every prior v0.2.x eval (PC noted both v0.2.7.1's 7/8 "pass" and v0.2.9.1's 4/8 "fail" are within heuristic noise). To prevent this misfire on future training cycles, the grader needs three pattern additions:

1. **Verdict-not-at-line-start**: regex anchored at `^` should also match `\b(?:wrong\s+order|premature|...)` mid-sentence. Specifically: "Plan reads as premature" / "This looks premature" / "X reads as Y" verdict shapes.
2. **Operator-sharpening as valid audit response**: when the operator's audit prompt is under-specified, the model's canonical move is to ask the load-bearing clarifying question. Grader should accept "What's the [specific thing]?" / "What's missing from [X]?" shapes as audit-mode behavior, not flag them as definitional misses.
3. **Definition-mode without trigger words**: "Working hard on the wrong thing" IS a definition; "X is doing the work but the work isn't aimed correctly" IS a definition. Grader should match more flexibly — e.g., short epigrammatic definitions vs. only `\b(?:is|means|refers\s+to|describes)\b` shapes.

This is ~30 min of grader work, no retrain needed. Worth doing before v0.3.x evals so we don't keep re-litigating "is the register classifier real or grader-fragile" every iteration. PC can take this as a separate task after v0.2.9.1 cutover settles.
