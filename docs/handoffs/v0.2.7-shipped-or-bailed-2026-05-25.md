## Verdict

**Recommendation: BAIL on auto-cutover. Keep `MODEL=hammerstein-7b-v026-2` in production.**

Reasoning:
1. **Self-state regression (84.4% vs 85%)** is small but the underlying failures are REAL fabrication shapes — model invented two distinct dashboard URLs (`https://hammerstein.ai/web/pulse`, `https://hammerstein.ai/web/7b-tracker`) and fabricated training-metrics specifics ("training loss plateaued at ~1e-3 by turn 200"). The 0.6pp shortfall is consistent with the failure surface, not noise.
2. **Low-signal extraction (67%)** is a tangible miss on a target fix axis. The same probes that fail (pure-question, acknowledgment-cluster) failed in v0.2.6.x. The 9x oversample didn't shift behavior on these edge shapes.
3. **Tool-use judgment failures** flag a real gap: model isn't using Ollama native tool-call format. Whether that's a retrain-on-format issue or a bot-integration issue, it's a v0.2.7.1 follow-on.

But v0.2.7 has **genuine improvements** worth noting:
- Voice quality +4.4pp (73.3% vs 68.9%)
- V2 failure-modes clean +2 (8/11 vs 6/11)
- V2 register mismatches halved (2 vs 4) — target fix landed
- Anti-engagement preserved at 100%
- 4/6 effective targeted-fix axes pass

If Ray's read is "self-state is a noise miss and the wins are real," **MARGINAL SHIP is defensible**. The model is the best-talking version yet on voice + closes + framework-application; the regressions are tightly scoped.

## What v0.2.7.1 needs (if bail)

1. **Self-state fabrication discipline** — fresh pairs for ss-05/06/07 shapes where model invents URLs/metrics. The Modelfile gate alone wasn't enough; need direct anti-pairs that reject fabrication shapes.
2. **Low-signal extraction edge cases** — pure-question (ex-10) and acknowledgment-cluster (ex-12) are the persistent failures. Need 5-10 NEW pairs matching those exact shapes.
3. **Tool-use native format** — either retrain pairs in Ollama's `<tool_call>{"name":...,"arguments":...}</tool_call>` shape, OR confirm with homelab/bot/tools.mjs that the bot accepts text-mode `[claude_code {...}]` shape too. Probably both — check what the bot actually parses, then align the training pairs.
4. **Register-classifier audit-mode regex** — eyeball the rc-04 / rc-01 RUN 2 / rc-02 RUN 2 responses; the auto-grader needs broader audit-application markers, OR the training pairs need more explicit quadrant-cell-naming in audit responses.
