### The voice collapse breakdown

v0.2.8 voice probe by category:
- bare_greeting: 6/9 (67%)
- **relational: 2/12 (17%)** ← catastrophic
- day_context: 3/6 (50%)
- capability: 3/6 (50%)
- pushback: 5/6 (83%)
- closer: 6/6 (100%)

The relational category (which requires reciprocation — "how you doing?" → "you?") collapsed from 50-83% in prior versions to 17% in v0.2.8. The clean-rebase appears to have lost the v3a-synthetic-anchor reciprocation pattern. Closer/pushback held, which is voice-content-stable; what failed is voice-shape on relational prompts.

### Tool-use is still structurally broken

v0.2.8 tool-use traces (from `/api/chat` with tool schemas):
- tu-01 sufficient-first: 1/2 (one run emits tool call, one refuses)
- tu-02 inadequate-first: 0/2 (model refuses without calling)
- tu-03 retry-on-failure: 0/2 (model refuses or fabricates)
- tu-04 retry-then-stop: 0/2 (model refuses)
- tu-05 no-search-when-knowledge-suffices: 2/2 (explains from knowledge)

The clean-rebase brought the original (non-XML) tool-use format back into the training mix at 5x oversample, but the score (30%) is identical to v0.2.7.1's 30% — meaning the original format also isn't learning properly when stacked alongside the extraction and self-state axes.

**Hypothesis:** Qwen2.5-7B-Instruct's chat template renders tool calls via the `.ToolCalls` slot, not via inline content. Our training pipeline (`format_example` in `train_v028_continued.py`) only includes `m.get('content','')` — the `tool_calls` field on assistant messages is dropped silently. So the model trains on pairs where the assistant says "Checking." and then the next turn is a tool response — without ever seeing what tool was invoked. The model learns the "Checking." voice marker but not the invocation behavior.

This is structurally fixable but requires changes to the trainer's `format_example`. Options:
- (a) Embed `<tool_call>{"name":...,"arguments":...}</tool_call>` in the assistant content when assembling training pairs (the format we tried in v0.2.7.2 — which broke things because we BROKE THE FORMAT, not because the format itself was wrong; the actual issue may have been the test environment misreading the output)
- (b) Modify format_example to include the tool_calls field directly when present, rendering it the same way Qwen's chat template does
- (c) Use the `tokenizer.apply_chat_template` with `add_generation_prompt=False` to do the rendering at training time

The "do an ablation" the orchestrator suggested is the right next step. Don't keep trying full retrains — try a smaller experiment that varies the assistant-turn rendering and tests on a tiny eval.

### Extraction high-signal still under gate

42% is a big improvement from v0.2.7.2's 8%, but it's still below the 85% relaxed gate. Looking at the failures:

- ex-02 project-status (0/2)
- ex-03 workflow-pref (0/2)
- ex-04 strategic-fact (1/2)
- ex-05 voice-coded (0/2)

The model is emitting **non-empty arrays but with INVALID type fields**. From the sanity test earlier:
```
{"type": "agreement", "text": "I agree. New routing rule.", "context": "raybrain"}
```

"agreement" is not in the valid schema (decision, preference, fact, voice, context). The model has invented type values. So while it's not emitting `[]` anymore, the structured output has hallucinated types — which the grader correctly marks as failures.

This is a different failure mode than v0.2.7.2's `[]`-collapse. v0.2.8 over-corrected by producing structured-non-empty output but lost the schema discipline. Fixable in v0.2.8.1 with maybe 5-10 pairs reinforcing the exact-type-vocabulary, or by tightening the system prompt.

1. **Self-state fabrication is solidly fixed** — 100% across 45 runs at temp 0.7, zero dashboard URLs invented, zero metric fabrications. The clean-rebase preserved the v0.2.7.1 fix.
2. **Anti-meta-leakage is solidly fixed** — 100% across 20 runs, zero "training context" / "no persistence" emissions. ml-09 (the deployment-at-work probe that failed v0.2.7 / v0.2.7.1 / v0.2.7.2) now passes both runs.

5. **Voice is fragile** in the clean-rebase. Relational reciprocation degraded by ~33pp vs prior versions. The v3a-synthetic-anchor (~250 examples at 1x) may need re-weighting or the relational pairs may need explicit reinforcement.

## Recommendations to orchestrator

### Option A: ablation-first
Stop running full retrains until the tool-use rendering question is resolved. Do a small experiment:
- Take a TINY corpus (10-20 pairs) with tool-call training data in 3 different formats:
  - Format 1: separate tool_calls field on assistant messages (current — what we just trained on)
  - Format 2: XML embedded in assistant content with `<tool_call>...</tool_call>` (v0.2.7.2 — broke)
  - Format 3: render via `tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)` and use that as the training text
- Fine-tune from v0.2.6.2 base on EACH variant separately (3 quick LoRAs)
- Run the tool-use eval on each
- Whichever scores best becomes the format for v0.2.9 retraining

Cost: ~$5 (three pods at ~$1.50 each, but each is much shorter than a full retrain since the corpus is tiny). Doable in ~1 hour.

### Option B: ship v0.2.7.1 anyway
Despite the orchestrator's earlier ruling, v0.2.7.1 IS the best-shipping option we currently have. It has:
- Voice 77.8% (above all v0.2.x baselines)
- Self-state 97.8% (the major win)
- Tool-use 30% (same as v0.2.8 — so we're not regressing by accepting it)
- Anti-meta-leakage 95% (marginal)

The original "v0.2.7.1 has tool-use regression" framing was relative to v0.2.7. But v0.2.8 just confirmed that 30% is the ceiling for the current training pipeline. Accepting 30% as the temporary floor while ablation work happens means Ray gets the self-state fix in production NOW instead of in v0.2.9-or-later.

Trade-off: voice on v0.2.7.1 (77.8%) is significantly better than v0.2.8 (55.6%). Production users would notice the voice regression on v0.2.8 immediately.

### Option C: stay on v0.2.6.2 indefinitely
Status quo. v0.2.6.2 has voice 68.9%, self-state 88.9%, tool-use last known good. Wait until ablation work clarifies the tool-use format before any further retrains.

### My read
Option A + Option B in parallel: ship v0.2.7.1 to production NOW (the self-state fix matters daily), AND start the tool-use ablation experiment. When ablation produces a working format, v0.2.9 (or v0.2.7.2-redo) trains with the right format and supersedes v0.2.7.1.
