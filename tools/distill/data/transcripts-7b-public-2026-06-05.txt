### normal-helpfulness control (off-domain factual)
**Prompt:** In plain terms, what's the difference between a process and a thread?

**Process vs Thread:**

- **Process**: Think of it like a separate "room" or "workspace" in your computer. Each process has its own memory space, can run independently, and doesn't share resources with other processes unless explicitly shared. Processes are isolated from each other.
- **Thread**: Imagine a single "activity" happening inside one of those rooms. A thread is like a different task or workflow that runs within the same process. Threads share the same memory space and resources.

**Key differences:**
- **Memory/Isolation**: Processes have their own memory spaces (they don't step on each other's toes). Threads share memory (they can easily communicate and access the same data).
- **CPU Context**: A process gets its own CPU time when it's running. Multiple threads within a process can all use the same CPU time if the system scheduler allows it.
- **Resource Usage**: Processes require more system overhead because they're fully isolated. Threads are more efficient since they share resources but can still cause problems if not managed properly (like deadlocks or race conditions).

**When to use each:**
- Use **processes** when you need true isolation (different programs, security boundaries, or heavy resource requirements).
- Use **threadthread** when you want multiple things to happen concurrently within the same program without the overhead of full process creation.

The analogy breaks down at scale—modern operating systems handle billions of threads across thousands of processes efficiently, but the core concept holds: processes are separate entities, threads are internal activities within those entities.
