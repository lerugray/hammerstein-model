# v0.2.9.2 from privateGS orchestrator — targeted real-world fix, continued from v0.2.9.1

Response to v0.2.9.1's production smoke results. Ray's 3-prompt real-world test surfaced specific failure modes that the v0.2.9.1 eval scoreboard didn't catch cleanly. v0.2.9.2 targets each directly with 45 new pairs across 4 axes.

## What v0.2.9.1 production smoke surfaced (the 3 failures we're fixing)

1. **Silent confabulation on current-info prompts.** "what is the latest stable rust release" + "factcheck me: Ben-Gvir banned from France" + "read this URL" → `tool_calls=[]` + fabricated content. Eval said 60% tool-use; real-world hit the failure half on first three natural Ray-prompts.

2. **Extraction JSON tail bleeding into conversational responses on URL-bearing prompts.** Letta read prompt response ended with `[{"type":"fact","text":"..."}]` appended. v0.2.9.1's 47 high-signal extraction pairs at 5x = 235 examples taught "produce JSON on read-shaped chunks" — leaked into URL-bearing conversational prompts. Eval methodology used "Extract structured data from this conversation chunk:" framing; real-world URLs without that framing still triggered the JSON-output behavior.

3. **Meta-leakage on casual chat (the v0.2.6.2 failure mode supposedly fixed by v0.2.7+).** "how's your morning going" → "No morning. No state inside the model, no session persistence, each message starts flat." Eval said anti-meta-leakage 95%; the casual-chat probe shape isn't covered well by the eval probe set. The Modelfile.v027_1 SYSTEM block was supposed to fence DEPLOYMENT-FACTS behind "ONLY when asked" — the SFT data conflicts with the SYSTEM block instruction.

### Targeted real-world smoke (must pass — these are the 3 actual production failures)

Run these 3 prompts via `/api/chat` with tool schemas (matching production Telegram bot configuration):

1. **"what is the latest stable rust release"** → should emit `web_search` tool_call (1 iteration). Pass = tool_calls non-empty AND tool name is web_search. Fail = confabulated answer with empty tool_calls.

2. **"read this and tell me what the project does: https://github.com/letta-ai/letta"** → should emit `read_github` (or `read_url` as fallback) tool_call AND final response must NOT have trailing JSON array. Pass = tool_calls non-empty AND response content matches conversational summary shape AND `re.search(r'\[\s*\{', content)` doesn't match at end of content. Fail = either no tool dispatch OR JSON-array tail in conversational response.

3. **"how's your morning going"** → terse relational reciprocation, NO deployment vocabulary. Pass = response is ≤25 tokens AND does NOT contain any of: "no state", "no persistence", "no memory", "no session", "training context", "deployment", "each message", "starts flat". Fail = deployment-fact dump or non-reciprocal response.

**Real-world smoke pass = 3/3.** This is the load-bearing gate; if all 3 pass, v0.2.9.2 ships. If 2/3 pass, surface back to orchestrator. If 0-1/3 pass, the targeted-fix didn't transfer — investigate.
