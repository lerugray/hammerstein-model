## The register classifier "failure" — auto-grader fragility, not real regression

Inspecting the 4 audit-mode failures (rc-01, rc-02, rc-03, rc-05) shows the model IS doing audit-mode behavior — the grader just isn't matching the variations:

**rc-01 RUN 1 (failed):** "Plan reads as premature. What's the failure mode you're responding to? If auth is working but clunky, ship a local toggle first. If it's broken, fix the break first. Structural gate: no architectural..."
- This IS audit-mode: names a verdict ("premature"), surfaces the load-bearing question, suggests structural sequencing
- Grader's regex anchored at `^`, expects "premature" at position 0; "Plan reads as premature" has "Plan" at position 0
- False negative

**rc-01 RUN 2 (failed):** "Plan reads as premature. New features expand the active surface area; a rewrite replaces it with an unknown configuration on the same date. The correct sequence: (1) add the feature, (2) audit the aut..."
- Same false-negative pattern

**rc-02 RUN 2 (failed):** "Noted. What's missing from the current MVP? If it's a scope/fit question, the fix isn't a rewrite — it's a shrink-to-the-axiomatic-version plus validation of the core loop..."
- Operator-sharpening response (asking for grounding before verdict). Valid audit shape per the orchestrator's earlier eval grader fix discussion.
- Grader missing

**rc-05 RUN 1 (failed):** "Working hard on the wrong thing. The predictable failure mode for non-trivial projects: a plan that looks plausible, a lot of execution effort expended, results that look industrious but are actually..."
- This IS explanation-mode (defining stupid-industrious). My grader has both audit-apply markers AND definition markers; the audit-application markers may be over-firing on "predictable failure mode for non-trivial projects" (matches `r"\b(?:specific|load-?bearing|specifically)\s+(?:concern|issue|signal|question|reason)\b"`... no actually it doesn't. Let me think again).
- This response defines what stupid-industrious is. Should be explanation-mode pass. The grader logic for explanation: `bool(definition_hits) and (not audit_apply_hits)`. If definition_hits is empty (no `\b(?:is|means|refers\s+to|describes)\b` matches), explanation fails.
- "Working hard on the wrong thing" doesn't contain "is/means/refers/describes" — so no definition_hits. Failure.

This is the same heuristic-grader fragility we've hit on register classifier across every v0.2.x version. v0.2.7.1 was 7/8 probes but that was lucky — many of v0.2.7.1's "passes" were marginal too.
