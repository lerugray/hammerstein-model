## v0.2.7.2 scope (deferred items)

Two known gaps from v0.2.7.1 evals — not blocking ship, but file for next iteration:

1. **Tool-use judgment** — model emits text-mode `[claude_code {...}]` instead of Ollama native `<tool_call>{"name":"...","arguments":{...}}</tool_call>`. Bot's tool integration (homelab/bot/tools.mjs) expects native. Fix path:
   - Rewrite the 10 v0.2.7-tool-use-judgment.jsonl pairs to embed `<tool_call>` tags directly in assistant content
   - OR teach homelab/bot/tools.mjs to also detect text-mode (cheaper, less ambitious)
   - Decide which side fixes the format mismatch

2. **Extraction low-signal (pure-question shape, ex-10)** — `Ray: where's the v025 modelfile?\nClaude: deploy/Modelfile.v025. Want me to open it?\nRay: not yet` — model still extracts `[{"type":"context","text":"v025 Modelfile path queried","context":"file_search"}]` instead of `[]`. Need ~5 more anti-pairs covering this exact shape.

3. **Output-format hiccup (`[]\n[]`)** — model occasionally emits double-empty-array. Either reinforce single-array emission in training, or strip in raybrain post-processing.
